# راهنمای نصب و استفاده فارسی BenX-UI

[English installation](easy-install.md) · [معرفی فارسی](../README.fa.md) · [وضعیت بررسی](validation-2026-11-15.md)

## معماری و پیش‌نیاز

پنل و API روی Cloudflare Worker، اطلاعات خصوصی روی D1 و فایل‌های رابط در Static Assets هستند. عامل لینوکس با دسترسی root روی VPS خودتان هسته‌ها را اجرا می‌کند. ترافیک VPN کاربران به VPS می‌رود؛ Worker مدیریت و اشتراک را انجام می‌دهد.

حساب GitHub و Cloudflare با اختیار ساخت Worker و D1، یک VPS با Debian 12/13 یا Ubuntu 24.04/26.04، معماری x86-64/ARM64، systemd، دسترسی root/sudo، HTTPS خروجی معتبر و ساعت درست لازم است. برای پورت، فایروال، forwarding و NAT پروتکل انتخابی برنامه داشته باشید. نصب بومی به پنل دیگر یا رله SSH عمومی نیاز ندارد.

## نصب با دکمه Cloudflare

۱. [مخزن BenX-UI](https://github.com/BenTheBuilder-BenX/BenX-UI) را باز و **Deploy to Cloudflare** را انتخاب کنید.

۲. با حساب‌های خودتان وارد شوید و مجوزهای درخواستی همان سرویس را بررسی کنید. Cloudflare یک کپی در حساب Git شما و دیتابیس خصوصی ایجاد می‌کند. ورود، مجوز حساب و آماده‌سازی واقعی منابع به تأیید شما نیاز دارند.

۳. تنظیمات زیر را نگه دارید:

| تنظیم | مقدار |
| --- | --- |
| نوع پروژه | Worker |
| مسیر | ریشه مخزن |
| Node.js | 24 |
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| D1 binding | `DB` مطابق Wrangler همراه پروژه |

۴. تا پایان انتشار صبر کنید. صرف نمایش آدرس Worker به معنی موفقیت همه مراحل نیست. خطای مرحله شکست‌خورده را در گزارش بررسی کنید.

۵. لینک خصوصی و یک‌بارمصرف راه‌اندازی را از انتهای گزارش انتشار باز کنید. **Create my login & sign in** اطلاعات ورود را تولید می‌کند. با **Copy login details** یا **Download login details** آن را ذخیره کنید و **Open my panel** را بزنید.

آدرس عمومی Worker اجازه تصاحب نصب جدید نمی‌دهد. ثبت‌نام عمومی وجود ندارد. گزارش انتشار و لینک فعال‌سازی را منتشر نکنید.

اگر دکمه در دسترس نبود، از **Workers & Pages → Create → Import a repository** کپی مخزن خودتان را وارد کنید و همان دستورها را بگذارید. تنظیمات تولیدشده D1 و کلیدهای نصب موجود را حفظ کنید. فایل نمونه شامل شناسه حساب، سرور یا کلید شخصی آماده نیست.

## نصب با خط فرمان

Node.js 24 و Python 3.11+ برای توسعه و تست مناسب‌اند:

```sh
git clone https://github.com/BenTheBuilder-BenX/BenX-UI.git
cd BenX-UI
npm ci
npx wrangler login
npm run deploy
```

لینک خصوصی چاپ‌شده را باز کنید. ساخت دستی دیتابیس، واردکردن SQL و ساخت دستی کلیدهای اولیه لازم نیست. نصب تازه ممکن است دو مرحله انتشار داشته باشد: آماده‌سازی دیتابیس و ثبت مالک نصب خالی، سپس بارگذاری کلیدها. HTTPS به آدرس Worker باید برقرار باشد.

در روش توکن، مجوز Cloudflare باید فقط منابع لازم حساب موردنظر را پوشش دهد. توکن را در مخزن یا کد رابط قرار ندهید.

## ورود، تغییر رمز و بازیابی

از **My account** رمز فعلی را وارد و نام کاربری یا رمز جدید را ذخیره کنید. برای تغییر فقط نام، رمز جدید را خالی بگذارید. رمز جدید ۱۲ تا ۱۲۸ کاراکتر و نام کاربری ۳ تا ۶۴ کاراکتر ASCII با نشانه‌های مجاز است.

نشست فعلی باز می‌ماند و نشست‌های قدیمی همان حساب باطل می‌شوند. تغییر ورود، کلید رمزگذاری و اتصال عامل‌ها را عوض نمی‌کند.

مالک باید **Private recovery information** را با رمز فعلی دانلود و کنار بکاپ کامل D1 در محل امن نگهداری کند. این فایل کلیدهای اصلی حساس دارد، بکاپ کامل نیست و رمز فعلی را ندارد. بکاپ کامل باید جدول `owner_account` را هم داشته باشد. کلید رمزگذاری نصب موجود را با کلید تازه جایگزین نکنید.

## اتصال VPS و اولین سرویس

۱. از **Getting started → Connect your VPS → Direct agent connection** اتصال بسازید.

۲. فایل خصوصی نصب را بررسی و روی همان VPS با root اجرا کنید. توکن جفت‌سازی بعد از ۲۰ دقیقه منقضی می‌شود؛ فایل را پس از استفاده حذف کنید. نصب‌کننده پیش از تغییر میزبان، دسترسی HTTPS احرازشده به Worker را بررسی می‌کند.

۳. اگر توکن منقضی شد، اتصال همان عامل را تمدید کنید. عامل متعلق به نصب دیگر را بازنویسی نکنید.

۴. اتصال عامل و وضعیت هسته را بررسی کنید. روشن‌شدن سرویس، اتصال موفق کلاینت یا صحت NAT را اثبات نمی‌کند.

۵. پروتکل، TLS/REALITY یا امنیت مناسب، ورودی و مشتری آزمایشی را بسازید. پروفایل/QR یا لینک اشتراک را به کلاینت بدهید. دامنه و گواهی موردنیاز پروتکل را بررسی کنید.

۶. اتصال واقعی، عبور ترافیک، غیرفعال‌سازی، انقضا، سهمیه پشتیبانی‌شده، قطع/وصل عامل و اتصال بعد از reboot را امتحان کنید.

ذخیره تنظیمات ممکن است فقط کار را در صف بگذارد؛ نتیجه واقعی عامل را بخوانید. مهلت پاسخ ۲۵ ثانیه است. در نتیجه نامشخص، پیش از تکرار عملیات حساس، وضعیت واقعی سرور را بررسی کنید.

## مدیر، نماینده و اشتراک

مالک به کل فضا دسترسی دارد. برای مدیر و نماینده نقش، محدوده سرور و محدودیت تخصیص را تعیین کنید. ورود مالک را مشترک نکنید. لینک اشتراک، پروفایل و QR اطلاعات خصوصی اتصال دارند؛ آن‌ها را عمومی منتشر نکنید. لغو/چرخاندن هویت و قطع سرویس را در کلاینت واقعی هم بررسی کنید. VPN بومی ممکن است فایل جدا در **Share** داشته باشد.

## دامنه، تونل و امکانات اختیاری

دامنه `workers.dev` برای پنل و اشتراک کافی است. ابزار دامنه پنل به توکن محدود جداگانه نیاز دارد؛ مجوز انتشار به برنامه درحال اجرا منتقل نمی‌شود. پیش‌نمایش را پیش از اعمال بخوانید. رکورد A/AAAA پشتیبانی‌شده DNS-only است؛ تعارض رکورد باید حل شود.

Cloudflare Access تعاملی را جلوی `/api/agent/*`، `/sub/*` یا webhook تلگرام نگذارید؛ عامل و کلاینت ورود تعاملی را پاسخ نمی‌دهند. بخش مدیریت می‌تواند محافظت اضافه سازگار داشته باشد.

برای تونل، هر دو سمت، handshake، داده واقعی، پورت/subnet، راه‌اندازی مجدد و پاک‌سازی را بررسی کنید. وضعیت running معادل عبور داده نیست. نصب خودکار با SSH مسیر پیشرفته‌ای است که به رله HTTPS خصوصی شما نیاز دارد؛ اتصال مستقیم عامل نیاز ندارد.

فروشگاه تلگرام و کمک هوش مصنوعی اختیاری‌اند و کلیدهای خودتان را می‌خواهند. Stars، رسید انتقال، تحویل، تکرار webhook و بازپرداخت را در محیط آزمایشی بررسی کنید. تست شبیه‌سازی‌شده اثبات پرداخت واقعی نیست.

## ظرفیت و هزینه

polling پیش‌فرض هر سه ثانیه تقریباً ۲۸٬۸۰۰ درخواست برای هر عامل در روز دارد؛ مدیریت، کرون و کاربران به آن اضافه می‌شوند. پشتیبانی از ذخیره ۵۰ سرور به معنی جاگرفتن ۵۰ عامل فعال در طرح رایگان نیست.

متغیر `AGENT_POLL_SECONDS` بین ۱ تا ۱۰ ثانیه است. مقدار بیشتر، درخواست کمتر و تأخیر فرمان بیشتر دارد؛ فاصله ۱۰ ثانیه حدود ۸٬۶۴۰ درخواست روزانه برای هر عامل است. مصرف واقعی Worker و D1 را در حساب بررسی کنید. [جزئیات انگلیسی ظرفیت](cloudflare.md).

فایل‌های نسخه‌دار رابط کش طولانی دارند؛ API و اشتراک خصوصی no-store هستند. صفحات مدیریتی و زبان‌ها تنبل بارگذاری می‌شوند. بررسی ظرفیت واقعی همچنان لازم است.

## ارتقا و خطایابی

قبل از ارتقا، بکاپ کامل D1 و کلیدهای اصلی را نگه دارید. کپی مخزن خودتان را به‌روز و `npm run deploy` را اجرا کنید؛ migrationها خودکارند. binding دیتابیس و کلیدها را با نصب تازه عوض نکنید.

| وضعیت | اقدام |
| --- | --- |
| لینک نصب گم شده و هنوز ورود ساخته نشده | `npm run setup:link` از محیط مجاز؛ لینک جدید را خصوصی باز و دستور عادی deploy را برگردانید. |
| رمز مالک بعد از فعال‌سازی گم شده | با کنترل حساب Cloudflare، `npm run account:recover` و لینک یک‌بارمصرف را استفاده کنید. |
| نصب اولیه پیش از ثبت کلید قطع شده | همه buildها/نصب‌های قبلی را متوقف کنید؛ فقط برای نصب خالی `npm run setup:resume` را بزنید. |
| برخی کلیدهای اصلی گم شده | همان مقادیر اصلی را از بازیابی خصوصی برگردانید؛ کلید تازه نسازید. |
| دیتابیس در حال تکمیل است | کمی صبر و refresh؛ migrationهای کامل حفظ می‌شوند. تداوم خطا نیاز به بررسی گزارش دارد. |
| عامل وصل نمی‌شود | ساعت، TLS، HTTPS خروجی، توکن، قواعد Access و `systemctl status benx-agent` را بررسی کنید. |
| خطای سهمیه یا 1102 | مصرف و محدودیت طرح Cloudflare، فاصله polling و تعداد عامل/کارهای کرون را بررسی کنید. |
| هسته روشن است اما کلاینت وصل نیست | پورت، فایروال، TLS/REALITY، forwarding/NAT، مسیر برگشت و پروفایل را روی VPS بررسی کنید. |

بازیابی به اختیار حساب Cloudflare نیاز دارد؛ endpoint عمومی بازیابی رمز نیست. لینک دزدیده‌شده تا زمان مصرف می‌تواند دسترسی مالک بدهد.

## تست و محدودیت

```sh
npm ci
npm run release:check
npm run release:package
```

نصب مستقل sing-box/Hysteria 2، اعمال عمومی IP/HWID بومی، وضعیت آنلاین بومی، تبدیل دلخواه پنل، جایگزینی خودکار شناسه منطقی عامل خروجی و کپی OS پیاده‌سازی نشده‌اند. سهمیه و اولین استفاده به آداپتور اندازه‌گیری‌شده نیاز دارند. MasterDnsVPN مستقل بدون حسابداری است؛ VLESS مشترک فقط داده داخلی را می‌شمارد.

[ماتریس امکانات](feature-matrix.md) و [پذیرش انتشار](release-acceptance.md) را بخوانید. تست‌های محلی سرویس خارجی و نصب لینوکس را شبیه‌سازی می‌کنند؛ جای نصب حساب واقعی، VPN، پرداخت، بازیابی روی VPS آزمایشی یا سنجش ظرفیت نیستند.
